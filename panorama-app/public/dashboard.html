Introduction to the Dashboard

The dashboard is your central hub for monitoring and managing your projects. This guide will help you navigate the various features and functionalities available.

Dashboard Home

Upon logging in, you will be directed to the main dashboard view where you can immediately see some overall statistics (ex. timeline, error stats) as well as a list of your projects.

Projects Overview

Here, you can view all your projects along with a brief timeline. You can click on a project to view its details and manage its settings.

Project Details

This is the dedicated project page view where you can see detailed information about a specific project (with some statistics), as well as a list of deployments under the project.

Deployment Details

This is the dedicated deployment page view where you can see detailed information about a specific deployment. Within this page, there are rows with an overview of each monitoring feature of the deployment including error tracking, performance metrics, and uptime monitoring data.

Deployment Errors

This page within the specific deployment view allows you to see some statistics related to the errors for the deployment, as well as a list of all error events (with options for filtering)

Deployment Performance

This page within the specific deployment view allows you to track performance metrics for the deployment. The metrics for backend services include CPU and memory usage while frontend metrics include important web performance indicators such as FCP, INP, LCP, and TTFB.

Deployment Uptime

This page within the specific deployment view allows you to track the uptime statistics for the deployment using timelines and charts. Also tracks response times.

Deployment Settings

Edit deployment settings such as its name, status, version, environment, API key, and type

Account Settings

Manage your account information including your name, email, and password.

Node.js SDK

The Node.js SDK provides a seamless way to integrate your Node.js applications with Panorama, allowing you to monitor and manage your applications effectively.

Installation

You can install the Node.js SDK using npm

npm install @panorama/sdk

Initialization

To initialize the SDK, you need to import the SDK, create an instance, and configure it with your API credentials for your deployment. 

import PanoramaClient from '@panorama/sdk'; // import SDK
const client = new PanoramaClient(); // create client instance
client.init({
  api_key: "sample_api_key_1_0", // API key for deployment
  id: 1, // deployment id
}); // can be done in an async function with await as well

Tracking Errors

Once you have successfully initialized the SDK, the client instance automatically tracks errors for the deployment.

You can also manually report errors using the captureError method.

try {
// some code that may throw an error
} catch (error) {
  client.captureError(error);
}

Breadcrumb Tracking

You can also track breadcrumbs for more context around errors using the addBreadcrumb method. The method takes in the following parameters:

  • message: A description of the breadcrumb
  • source: The source of the breadcrumb (ex. navigation, user, log)
  • type: The type of the breadcrumb (info, warning, error, debug)
client.addBreadcrumb({
  message: "User clicked on button",
  source: "user",
  type: "info"              
})

Tracking Performance

The SDK also automatically tracks performance metrics for the deployment (CPU and memory usage).

Just note that tracked performance metrics are relative to the deployment's environment.

Benchmark Tracking

You can measure the performance of different parts of your application using the benchmarking features.

To start benchmarking, you can use the beginBenchmark method.

client.beginBenchmark("benchmark_name");

To end the benchmark, you can use the endBenchmark method.

client.endBenchmark("benchmark_name");

Tracking Uptime

Uptime metrics are automatically tracked by the Panorama server, including response times and availability statistics.

Note that uptime metrics require a public endpoint to be accessible.
